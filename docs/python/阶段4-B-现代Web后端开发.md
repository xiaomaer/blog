# 阶段四 · 方向 B：现代 Web 后端开发

本文将[资深前端开发学习 Python 的路线图](%E8%B5%84%E6%B7%B1%E5%89%8D%E7%AB%AF%E5%BC%80%E5%8F%91%E5%AD%A6%E4%B9%A0python%E7%9A%84%E8%B7%AF%E7%BA%BF%E5%9B%BE.md)中的现代 Web 后端方向展开为可实践的学习模块。

**学习目标：** 能独立设计、实现、测试和部署业务服务，完成一个具备权限控制、分页和异步导出能力的项目管理后端。

**适用场景：** 全栈应用、管理系统、数据 API 和任务服务。重点关注数据一致性、权限边界、并发和失败处理。

**前置能力：** 能独立管理 Python 环境、使用类型提示、编写 Pytest 测试，并理解 `async/await`、异常处理和上下文管理器。后续可结合[方向 A：AI 与大模型应用开发](%E9%98%B6%E6%AE%B54-A-AI%E4%B8%8E%E5%A4%A7%E6%A8%A1%E5%9E%8B%E5%BA%94%E7%94%A8%E5%BC%80%E5%8F%91.md)加入信息抽取、知识库问答和工具调用能力。

## 前端知识迁移

以下对照描述的是相近职责，不代表 API 和行为完全一致。

| 已有前端 / Node.js 经验 | Python 侧重点 |
| --- | --- |
| TypeScript 类型 + Zod 校验 | 类型提示 + Pydantic 运行时校验；仅有类型提示不会自动校验外部输入 |
| 控制器、服务、依赖注入 | FastAPI 路由、业务函数、`Depends` 和资源生命周期 |
| Prisma / TypeORM、数据库事务 | SQLAlchemy 映射、会话、事务和连接池 |
| `fetch`、流式响应、请求取消 | 异步 HTTP 客户端、异步生成器、超时和取消传播 |
| Vitest / Jest、模拟对象、集成测试 | Pytest fixture、参数化、依赖覆盖和 API 测试 |

## 学习顺序

**顺序：** API 与数据建模 → 数据库与事务 → 身份认证与权限控制 → 并发与任务 → 测试与部署 → 综合项目。以 FastAPI 为入口，重点掌握服务行为和数据正确性，在真实工作负载下通过测量评估性能。

## B1. FastAPI 与 API 契约

* **请求与响应：** 学习路径参数、查询参数、请求体、请求头、状态码、文件上传和响应模型。设计稳定的分页、过滤、排序和错误格式。
* **Pydantic 模型：** 分开设计创建、更新和响应模型。在 PATCH 请求中区分“未提供字段”和“显式传入空值”，避免误清空已有数据。
* **API 契约：** 使用 OpenAPI 文档进行前后端联调。约定时间、金额、枚举和空值的序列化方式。响应中排除密码哈希等内部字段。
* **依赖与生命周期：** 使用 `Depends` 管理当前用户、数据库会话和配置。学习带 `yield` 的依赖清理及应用生命周期管理，用于管理连接池和共享客户端。
* **职责划分：** 路由处理 HTTP 输入输出，业务函数表达业务规则，数据库模型负责持久化。随着应用增长按功能拆分，避免为简单功能引入不必要的分层。

从 [FastAPI 官方教程](https://fastapi.tiangolo.com/tutorial/)开始。

**练习：** 实现任务创建、详情、列表、局部更新和删除 API，并接入已有的前端列表页。

**验收标准：** 合法请求、参数错误、资源不存在和分页边界均有明确行为。前端能依据文档完成联调，响应不会暴露内部字段。

## B2. PostgreSQL、SQLAlchemy 与事务

* **SQL 基础：** 学习主键、外键、唯一约束、非空约束、连接查询、聚合和索引。阅读生成的 SQL 与查询计划，理解 ORM 背后的数据库行为。
* **现代 ORM 用法：** 学习 SQLAlchemy 2.x 的 `Mapped`、`mapped_column`、`select()` 和关系映射。区分引擎、连接池与会话的职责。
* **事务边界：** 区分 `flush`、`commit` 和 `rollback`。需要共同成功的写操作应置于同一事务中，并通过数据库约束防止并发产生重复数据。
* **会话生命周期：** 按请求管理会话并及时释放资源。如果一个请求启动多个并发数据库任务，每个任务仍需独立的 `AsyncSession`，不能并发共享同一个会话。
* **查询质量：** 识别 N+1 查询，学习使用 `selectinload` 等方式预加载。注意异步代码中属性访问触发的隐式 I/O。比较偏移量分页与游标分页的适用场景。参考 [SQLAlchemy 异步 ORM 文档](https://docs.sqlalchemy.org/en/20/orm/extensions/asyncio.html)。
* **数据库迁移：** 学习 Alembic 迁移版本、升级和降级。自动生成的迁移只是待审查方案，尤其要检查重命名、数据回填和约束变更；自动生成并不保证安全。参考 [Alembic 自动生成文档](https://alembic.sqlalchemy.org/en/latest/autogenerate.html)。
* **SQLModel 的定位：** SQLModel 是结合类型化模型与 ORM 能力的一种选择，但 SQL、会话和事务仍是必备知识。即使复用字段定义，也要区分 API 模型与数据库表模型。

**练习：** 创建用户、项目、成员关系和任务表。实现“创建项目并添加初始成员”的原子操作，再执行一次包含数据回填的数据库结构迁移。

**验收标准：** 中途失败不会留下部分业务记录。并发创建不能绕过唯一约束。空数据库与上一版本数据库都能迁移到目标结构。能解释一次列表请求执行的 SQL。

## B3. 身份认证、权限控制与输入边界

* **认证与会话：** 理解密码哈希、登录状态、Bearer 令牌和 Cookie 会话。使用 JWT 时，学习签名、过期时间、签发者和受众校验，以及退出登录与撤销策略。
* **权限控制：** 区分身份与权限，为项目成员、普通用户和管理员实现角色权限与资源归属校验。
* **数据隔离：** 在列表、详情、更新、删除和导出操作中落实数据访问边界。请求中传入的用户或项目 ID，必须与当前身份的权限进行核对。
* **浏览器交互：** 区分 CORS 与身份认证。使用 Cookie 携带凭据时，学习 `HttpOnly`、`Secure`、`SameSite` 和 CSRF 防护。
* **输入与输出：** 限制上传大小和类型，使用参数化查询，避免暴露内部错误细节。对重要业务操作记录操作者、资源和结果。

**练习：** 为项目 API 加入管理员 / 成员权限及项目级数据隔离。

**验收标准：** 使用两个用户尝试访问彼此的列表、详情、更新和导出 API，确认越权访问被拒绝。过期或无效凭据不能访问受保护资源。

## B4. 异步执行、缓存与后台任务

* **异步边界：** 使用异步 I/O 客户端时学习 `async def`。由 FastAPI 管理、使用普通 `def` 声明的路由和依赖会在线程池中运行，但在 `async def` 内直接调用的同步函数不会自动转移到线程池。参考 [FastAPI 并发指南](https://fastapi.tiangolo.com/async/)。
* **资源控制：** 为外部请求配置超时、连接池和并发上限。处理取消、连接释放和服务关闭。CPU 密集型工作应评估进程池或独立工作进程；添加 `async` 不会让计算自动并行。
* **缓存：** 使用 Redis 练习旁路缓存（Cache-Aside）、TTL、更新后的失效处理和热点数据缓存。缓存键应包含用户或租户边界及查询条件。明确缓存暂时不可用时的行为。
* **后台任务：** 区分进程内的 `BackgroundTasks` 与独立任务队列。任务需要跨进程执行、持久化或失败重试时，学习基于工作进程的队列。参考 [FastAPI 后台任务文档](https://fastapi.tiangolo.com/tutorial/background-tasks/)。
* **任务可靠性：** 理解任务可能被重复投递。设计任务 ID、状态查询、幂等处理逻辑和重试上限。后续再学习数据库提交与消息发布之间的一致性。
* **实时反馈：** 学习用 SSE 推送单向进度、用 WebSocket 实现双向交互。理解为什么进程内的连接列表不能直接支持多个工作进程之间的广播。

**练习：** 将项目报表导出移到后台任务中。立即返回任务 ID，由前端查询进度并在完成后下载文件。

**验收标准：** 导出期间普通 API 仍能响应。失败任务有明确状态。重复执行不会产生重复业务副作用，缓存和任务结果不会跨用户泄露。

## B5. 测试、部署与可观测性

* **测试分层：** 使用 Pytest 测试业务规则，用 API 测试验证请求响应行为，并使用真实测试数据库验证事务和约束。通过 fixture 和依赖覆盖隔离环境。
* **关键场景：** 覆盖非法输入、未认证请求、越权访问、唯一约束冲突、事务回滚、分页边界、外部服务超时和任务重试。隔离各测试的数据。
* **配置与部署：** 学习环境变量、配置校验、依赖锁定、Docker 镜像和 ASGI 服务启动。明确数据库迁移、Web 服务和工作进程的启动顺序。
* **进程与连接池：** 理解每个工作进程可能维护独立的数据库连接池。根据实例数、工作进程数和每个连接池的上限估算数据库总连接数。
* **生命周期与恢复：** 配置健康检查、就绪检查和优雅关闭。演练应用重启、数据库暂时不可用和数据库备份恢复。
* **日志与指标：** 记录请求 ID、状态码和延迟。监控错误率、延迟分位数、连接池等待和任务积压。避免记录密码、令牌和敏感请求体。
* **性能验证：** 在注明硬件、数据集大小、并发数和请求类型的条件下进行压测。依据慢查询、阻塞调用或资源饱和情况优化；仅凭框架名称不能判断性能。

**练习：** 组合应用、数据库和任务组件，完成本地部署，运行 API 测试并演练一个故障场景。

**验收标准：** 干净环境能按说明启动。关键测试可重复执行。能通过日志定位失败请求，并解释性能瓶颈和部署资源限制。

## B6. 综合项目与结业标准

**项目：团队项目与任务管理后端。** 复用前端经验，将学习重点放在 Python 服务的数据、权限和交付上。

* [ ] 在统一 API 契约下支持登录、项目成员管理和任务增删改查。
* [ ] 支持权限隔离、分页、过滤和排序，覆盖越权访问与资源不存在场景。
* [ ] 使用关系型数据库持久化数据，通过迁移管理结构变更，并验证关键操作的事务回滚。
* [ ] 支持报表异步导出、进度查询、失败反馈和幂等重试。
* [ ] 具备关键业务测试、API 测试及基于真实数据库的集成测试。
* [ ] 提供部署说明、示例配置、健康检查和结构化日志，支持重复部署与演示。

**后续可选专题：** 深入事务隔离、消息一致性、分布式追踪、性能剖析和服务拆分。先用单体应用建立完整交付能力，再根据规模和领域边界扩展。

## 与 AI 方向衔接

完成 B1–B6，交付业务后端后，再结合 [AI 方向](%E9%98%B6%E6%AE%B54-A-AI%E4%B8%8E%E5%A4%A7%E6%A8%A1%E5%9E%8B%E5%BA%94%E7%94%A8%E5%BC%80%E5%8F%91.md)的 A2 信息抽取或 A3 知识库问答，将 AI 接入已有业务流程。

**联合验收场景：** 在项目管理系统中加入“查询项目文档 → 总结待办事项 → 获得用户确认 → 创建任务”。验证来源引用、用户权限、任务幂等性和完整调用记录。

用每个模块的验收标准衡量进度。能够解释数据流、复现失败并交付可运行项目，才算完成学习。

# 阶段四 · 方向 A：AI 与大模型应用开发

本文将[资深前端开发学习 Python 的路线图](%E8%B5%84%E6%B7%B1%E5%89%8D%E7%AB%AF%E5%BC%80%E5%8F%91%E5%AD%A6%E4%B9%A0python%E7%9A%84%E8%B7%AF%E7%BA%BF%E5%9B%BE.md)中的 AI 方向展开为可实践的学习模块。

**学习目标：** 将模型、业务数据和工具连接为可靠的 AI 功能，完成一个支持来源引用和工具调用的技术文档助手。

**适用场景：** 知识库问答、信息抽取和业务助手。重点关注输出的不确定性、检索质量、工具权限、成本和评估。

**前置能力：** 能独立管理 Python 环境、使用类型提示、编写 Pytest 测试，并理解 `async/await`、异常处理和上下文管理器。需要将应用作为服务对外提供时，结合[方向 B：现代 Web 后端开发](%E9%98%B6%E6%AE%B54-B-%E7%8E%B0%E4%BB%A3Web%E5%90%8E%E7%AB%AF%E5%BC%80%E5%8F%91.md)学习 API 设计、身份认证、权限控制和部署。

## 前端知识迁移

以下对照描述的是相近职责，不代表 API 和行为完全一致。

| 已有前端 / Node.js 经验 | Python 侧重点 |
| --- | --- |
| TypeScript 类型 + Zod 校验 | 类型提示 + Pydantic 运行时校验；仅有类型提示不会自动校验外部输入 |
| `fetch`、流式响应、请求取消 | 异步 HTTP 客户端、异步生成器、超时和取消传播 |
| 控制器、服务、依赖注入 | FastAPI 路由、业务函数、`Depends` 和资源生命周期 |
| Vitest / Jest、模拟对象、集成测试 | Pytest fixture、参数化、依赖覆盖和 API 测试 |

## 学习顺序

**顺序：** 模型调用 → 结构化输出 → RAG → 工具调用与智能体 → 评估与服务交付 → 综合项目。主线聚焦应用工程，模型训练和微调可作为后续专项方向。

## A1. 模型调用与流式交互

* **请求生命周期：** 通过模型供应商的 Python SDK 或 HTTP API 发起请求，理解输入消息、模型参数、响应内容、结束原因和用量统计。
* **核心概念：** 理解 token、上下文窗口、输入输出预算和采样参数。不同模型支持的参数存在差异，降低随机性也不意味着结果完全可复现。
* **提示词组织：** 分开管理任务指令、用户输入和参考材料。练习明确输出要求、提供少量示例和对提示词进行版本管理。
* **流式处理：** 通过异步迭代接收增量结果，区分文本片段和工具调用事件。通过 SSE 或流式 HTTP 将结果传给前端，处理加载、完成、错误和用户取消。
* **可靠调用：** 配置超时、并发上限以及带退避策略的有限重试。区分限流、临时服务故障与参数错误、认证失败，避免对所有错误一律重试。凭据保存在服务端。

**练习：** 实现一个文章摘要命令行工具，再接入前端页面展示流式结果。

**验收标准：** 能展示完整结果和增量结果。模拟超时、限流和用户取消时，程序能结束并释放资源。记录一次请求的延迟和用量。

## A2. Pydantic 与结构化输出

* **数据建模：** 学习 `BaseModel`、`Field`、嵌套模型、枚举、默认值、字段约束，以及 `field_validator` / `model_validator`。
* **类型边界：** 区分允许 `None` 的字段与可以省略的字段。理解默认类型转换、严格模式和额外字段的处理策略。
* **校验与序列化：** 学习 `model_validate()`、`model_validate_json()`、`model_dump()`、`model_dump_json()` 和 `model_json_schema()`，区分 Python 对象、JSON 字符串与 JSON Schema。参考 [Pydantic 模型文档](https://docs.pydantic.dev/latest/concepts/models/)。
* **输出约束：** 区分提示词要求输出 JSON、供应商原生结构化输出，以及通过工具调用实现的结构化输出。选择模型支持的方式，校验业务规则，并处理拒绝回答、输出截断和校验失败。参考[结构化输出文档](https://docs.langchain.com/oss/python/langchain/structured-output)。
* **业务正确性：** Schema 约束的是结构和已声明的规则，不能保证事实准确。例如，抽取出的负责人必须对应真实用户，日期必须满足业务约束。

**练习：** 从会议记录中抽取主题、待办事项、负责人和截止日期，用明确的空值表示缺失信息。

**验收标准：** 合法输入能转为带类型的对象。能发现必填字段缺失、枚举值不合法和日期格式错误。信息缺失时，应用不会编造负责人或日期。

## A3. RAG：接入自己的知识库

检索增强生成（RAG）的基本流程为：**读取文档 → 清洗与切分 → 向量化 → 存入索引 → 检索 → 组装上下文 → 生成带引用的回答**。先掌握固定的“先检索、后生成”流程，再学习由智能体决定何时检索。参考 [RAG 组件与架构](https://docs.langchain.com/oss/python/deepagents/retrieval)。

* **数据接入：** 从 Markdown 和纯文本开始，保留文档 ID、标题、来源、更新时间和权限元数据。再扩展到 PDF 和网页，并检查解析质量。
* **文档切分：** 对比按长度、段落和标题层级切分。理解片段大小、重叠范围与上下文完整性之间的取舍，避免拆散代码块或操作步骤。
* **向量表示：** 理解文本向量、相似度和维度。查询与文档的向量表示必须使用兼容的模型。更换模型后需要重新评估，通常还需要重建索引。
* **向量存储：** 在 Chroma 或 Milvus 中练习集合创建、写入、检索、元数据过滤、更新和删除。检查持久化及重启后的恢复。参考 [Chroma 快速入门](https://docs.trychroma.com/docs/overview/getting-started)和 [Milvus 快速入门](https://milvus.io/docs/quickstart.md)，初期完成其中一个即可。
* **检索改进：** 学习 Top-K 检索、关键词与向量混合检索、重排序和查询改写。在同一组样例上对比结果，区分“没有检索到资料”与“检索正确但回答错误”。
* **更新与隔离：** 处理重复导入、文档变更和删除。在检索阶段落实用户权限，确保无权访问的内容不会进入模型上下文。
* **回答依据：** 记录检索片段，并返回能定位来源的引用。证据不足时明确说明；将检索文档作为参考材料，不将其视为可以覆盖系统规则的指令。

**练习：** 基于自己的技术笔记实现问答程序，支持增量导入、文档删除和来源引用链接。

**验收标准：** 准备可直接回答、需要跨文档回答、没有答案和涉及未授权内容的样例。分别评估检索结果与最终回答。删除文档后，后续检索和引用不再使用被删除的内容。

## A4. 工具调用、智能体与框架

* **工具调用协议：** 理解完整循环：模型提出工具及参数 → 程序校验并执行 → 返回工具结果 → 模型继续回答。模型发起工具调用不代表业务操作已经完成。
* **工具定义：** 明确每个工具的用途、输入 Schema、输出结构和错误语义。区分只读查询与会改变业务状态的操作。
* **执行边界：** 在服务端校验身份和权限。为写操作加入确认步骤和幂等控制。限制循环轮次、工具调用次数、执行时间和费用。
* **状态管理：** 区分对话历史、当前任务状态和长期存储。学习失败恢复与人工介入，避免重试导致重复写入。
* **流程编排：** 固定步骤采用显式工作流；下一步依赖中间结果时，再引入智能体。先理解调用过程，再用框架减少重复工作。参考 [LangChain 智能体文档](https://docs.langchain.com/oss/python/langchain/agents)。

| 学习方式 | 关注点 | 需要理解的取舍 |
| --- | --- | --- |
| 直接使用模型 SDK | 提示词、工具协议、流式事件和调用循环 | 需要自行组织状态、重试和调用追踪 |
| LangChain | 模型与工具集成、智能体、结构化输出 | 需要理解框架抽象和版本变化 |
| LlamaIndex | 文档接入、索引、检索和知识库问答，并可扩展智能体能力 | 需要理解数据组件与查询组件的连接方式 |

这些能力存在重叠，无需学习所有框架。可以用同一个小练习比较其抽象方式。LlamaIndex 可从[概念文档](https://developers.llamaindex.ai/python/framework/getting_started/concepts/)入手。

**练习：** 为文档助手提供三个工具：搜索文档、查询任务和创建任务草稿。用户确认后才创建实际任务。

**验收标准：** 每次工具调用都可追踪。非法参数和未授权请求会被拒绝。工具超时能返回错误，达到轮次上限后循环停止，重复提交不会创建重复任务。

## A5. 评估、成本与服务交付

* **固定评估集：** 准备真实问题及参考答案或评判标准，覆盖正常、歧义、无法回答、来源冲突和恶意指令等场景。开发样例与最终验收样例分开。
* **分层评估：** 分别检查结构有效性、检索召回率、回答依据、引用准确性和工具任务完成情况。结合自动评分与人工抽查，避免仅凭几次对话判断质量。
* **回归对比：** 提示词、切分方式、模型或检索参数变化时，使用同一套评估集比较，记录版本和失败样例。
* **成本与性能：** 记录首个输出片段的延迟、总延迟、token 用量、工具调用次数和单任务成本。设置会话预算，更换模型前比较质量与成本。
* **测试边界：** 日常测试中模拟模型响应，验证业务逻辑。用少量真实调用完成集成验证和质量评估，不要求每次生成的文字逐字一致。
* **服务交付：** 用 FastAPI 暴露聊天、文档导入和任务查询 API。学习流式连接断开后的清理、后台导入、用户隔离、限流和日志脱敏。缓存键必须包含影响结果的条件，例如用户权限和知识版本。

**练习：** 对比两组提示词或切分配置，制作包含质量、延迟、成本和失败案例的评估表。

**验收标准：** 能用记录下来的证据解释改进与退步。测试覆盖模型不可用、检索结果为空、工具参数非法和流式连接中断。日志能支持排障且不会泄露凭据。

## A6. 综合项目与结业标准

**项目：个人技术文档助手。** 沿用熟悉的前端技术栈，由 Python 负责文档处理、检索、模型调用和工具执行。

* [ ] 支持 Markdown 文档导入、更新和删除，重复导入不会产生重复数据。
* [ ] 支持流式回答、取消、来源引用，并在证据不足时明确提示。
* [ ] 能抽取结构化待办事项，并在确认后创建任务。
* [ ] 实现用户隔离，在检索和工具执行时均检查权限。
* [ ] 具备固定评估集、关键失败场景测试，以及延迟和成本记录。
* [ ] 提供启动说明和示例配置，能从干净环境重新部署并演示完整流程。

**后续可选专题：** 多模态输入、本地推理、微调、复杂工作流和多智能体协作。围绕项目瓶颈按需学习，不将其作为完成本方向的前置条件。

## 与后端方向衔接

先完成 A1–A3，做出可以评估的应用；再结合[后端方向](%E9%98%B6%E6%AE%B54-B-%E7%8E%B0%E4%BB%A3Web%E5%90%8E%E7%AB%AF%E5%BC%80%E5%8F%91.md)的 B1、B3、B5 补齐 API、权限控制和部署能力，随后接入 A4 的业务工具。

**联合验收场景：** 在项目管理系统中加入“查询项目文档 → 总结待办事项 → 获得用户确认 → 创建任务”。验证来源引用、用户权限、任务幂等性和完整调用记录。

用每个模块的验收标准衡量进度。能够解释数据流、复现失败并交付可运行项目，才算完成学习。
